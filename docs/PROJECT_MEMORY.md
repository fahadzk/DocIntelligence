# Project Memory

- Development uses one main agent. Do not spawn sub-agents or delegate architecture, implementation, testing, documentation, or integration work. The main agent owns decisions and completes each development increment end to end.
- The application is local-first and desktop-first. Electron delivers the UI; FastAPI owns application behavior; frontend code never accesses databases directly.
- Phase 2 adds import and extraction for text PDFs, DOCX, UTF-8 TXT, and Markdown. Phase 3 adds local Search and grounded Ask. OCR, graphs, cloud, and accounts remain out of scope until scheduled.
- Canonical development data lives in project `data/`; migration version 2 retains existing projects and imports rows once from the former `backend/data` database. Production data paths must use the Electron user data directory.
- Each document owns `documents/<project UUID>/<document UUID>/original.<type>` and `content.json`. Processing status is persisted. Startup marks incomplete work interrupted and retryable; ready requires both files.
- Import uses multipart bytes from the file picker. Backend never accepts an arbitrary source path. The default maximum is 50 MB and duplicate hashes are rejected per project.
- SQLite migration version 3 owns source-located passages, FTS5 keyword search, and durable index state. Chroma vectors are derived and replaceable; original content.json remains the source of truth for rebuilding.
- Local FastEmbed BGE-small English embeddings (MIT) and Qwen2.5 1.5B Instruct GGUF answers (Apache 2.0) are optional, app-provisioned, and work offline after download. Keyword search never requires a model.
- The answer runtime checks for at least 2.5 GB free RAM before a cold load. On the development dual-core 8 GB Windows laptop, leave closer to 3 GB free for practical performance; Search still works when Ask cannot load.
- Citation evidence is resolved through live, project-scoped SQLite passages; deleted documents cannot be cited. A cited model response still requires user judgment and is not a factual guarantee.
- The visual direction is “Calm Intelligence”: neutral, evidence-first, professional, and not chatbot-centric.
- APIs return explicit Pydantic contracts. Missing projects use `PROJECT_NOT_FOUND` and no internal trace is exposed to users.
- Operational events use standard-library queue-based JSON Lines logging at `logs/document-intelligence.jsonl` below the configured data directory. File I/O is handled by a background listener, files rotate at 10 MB with five backups, and logs carry safe metadata/timings but never raw document text, prompts, or generated answers. The former migration 4 activity table is retained only for existing-database compatibility.
- Pipeline Lab is a separate advanced workspace. Standard always uses the values in `config/pipeline_defaults.py`; Lab resolves validated project overrides through `PipelineConfigService`. Never let Lab overrides change Standard passages, vectors, or citation behavior.
- Pipeline Lab settings autosave after a short debounce, serialize writes, and keep newer edits when a slower save completes. The UI reports pending/saving/saved/error and offers retry. Keep Lab mounted after first opening so switching workbenches does not discard in-progress state. Standard status polling pauses during Ask and while Lab is active.
- The UI uses neutral Fluent-inspired surfaces, a restrained blue action/focus accent, and responsive navigation that keeps projects reachable at narrow widths. Semantic success/warning/error colors remain distinct from the brand accent.
- UI colors now resolve through semantic light/dark tokens in `frontend/src/styles/global.css`. Appearance (Light, Dark, System) is a local UI preference stored under `document-intelligence.theme`; System follows OS changes. Fluent System Icons are wrapped by one icon component. Standard Documents/Search/Ask and Pipeline Lab share the same evidence presentation but retain separate backend behavior.
- The desktop sidebar is pinned by default; `document-intelligence.sidebar-pinned` stores the reversible preference. Unpinned mode is an icon rail that temporarily expands on hover or keyboard focus. The sidebar is viewport-height, only the project list scrolls, and Settings stays fixed at the bottom. The pin control is at the top of the main workspace.
- In collapsed mode the rail shows only the active project icon; selecting it pins the full project list open, while hovering still temporarily reveals every project. Do not add a color per project: the selected state and accessible names carry identity without a noisy palette.
- Standard and Lab share the same local FastEmbed instance and Chroma persistence directory. Serialize embedding-model use and Chroma client/collection initialization across their background index threads; concurrent Chroma startup previously failed on Windows.
- SQLite migration v5 stores project Lab overrides plus separate Lab passages, FTS, and index state. Lab Chroma vectors use a separate collection. The Lab document configuration hash triggers reindexing from retained extracted content.
- Built-in plugins are discovered at backend startup from `app/plugins/builtins`; the React registry request is cached once per session. No user-installable plugins or external plugin folders.
- Lab cloud credentials live only in the operating system credential vault through `keyring`. Provider model IDs are discovered dynamically. Cloud Ask sends selected evidence and question text to the chosen provider; Standard never calls a hosted model.
- As implemented, Standard Ask selects at most three passages and has no extractive fallback after failed answer validation. Older ADR-003 prose saying five passages/fallback is superseded by ADR-005.
